一句话概括

在 dsh 官方设置页左侧栏加一个「文字注入」分区：把两段文本分别注入到 system 系统提示词（每轮生效）或 context 会话上下文（合成一条 user 消息）。 内容写在你自己的一份 inject.md 里，改文件即热加载，每次保存自动留备份。

功能清单（点开看实现）

数据文件格式

# 任意标题（说明用，解析器忽略）

## [system] 我的常驻规则
order: 40

这段会追加进系统提示词，每轮生效。

## [context] 项目背景
kind: gw-project
trigger: 项目,需求

当消息里出现「项目」或「需求」时，这段作为一条 user 消息注入会话。
  • 块头 ## [system] 名称 / ## [context] 名称，大小写不敏感
  • 元数据只认 order / kind / trigger / enabled，英文冒号，必须紧跟块头
  • 一旦出现非元数据非空行，后面全是正文 —— 所以正文里的「中文：」不会被误解析（这点设计得挺好）
  • enabled: false 临时禁用；trigger 留空 = 每轮注入

问题诊断

下面每条都对着源码 / 官方 typert 类型声明核过，不是凭感觉。点卡片展开证据。

严重性排序（我的判断）

  • P0 注入的 user 消息 source 不合法 —— 游离 kind 会污染会话派生与前端渲染，属于「协议层错误」，必须改
  • P0 没有预览 —— 「模型到底看到了什么」看不见，这是「不太好用」的第一感受来源
  • P1 去重语义错 —— 只在本轮 messages 里找 kind，跨轮必然重复注入
  • P1 system 段硬套 ---- 分隔线 —— 装饰符号进提示词，模型会看到莫名横线
  • P1 fs.watch 盯单个文件 —— 编辑器保存（替换文件）后监听会失效，热加载静默失灵
  • P2 config 无 schema 校验；save 不做结构校验；历史无 diff；UI 无排序/无 order 可视化/无变量支持

我推测你想要的效果

核心诉求应该是：「我写的东西，到底以什么形态、在什么时机进了模型的上下文」要一眼看见、随手能改、改完立刻生效。 所以 v2 把它做成一个注入工作台：左边是块清单、中间是编辑器、右边是"模型视角"的实时预览 —— 预览里能直接看到你的段落在整条系统提示词里的位置，以及会合成出什么样的 user 消息。

下面这个原型是可以真的点的：改文字、切启停、调 order、换模拟输入，右侧和 inject.md 预览都会实时跟着变。

相对 v1 的新增点

🔍 真实预览

host 侧新增 /preview，直接调用 systemPrompt.assemble() 拿到装配后的段列表，标出哪几段是你注入的、落在哪个 order 区间。

🧩 变量支持

复用框架已有变量 {{provider}} {{model}} {{cwd}}，编辑器里给出可用清单和未注册变量的红字提示。

🎚 order 可视化

把官方段序列（-1000 … 9900）画成一条轴，你的段直接落在轴上，不再靠猜「40 是插在哪」。

🕓 带 diff 的历史

备份列表可预览、可 diff、可命名；恢复前先预演「恢复后会变成什么样」。

✅ 实时校验

kind 唯一 / 名称不重复 / order 合法 / 变量已注册 / 正文非空 —— 边写边报，不等保存。

📥 导入导出

整份配置导出 .md；从粘贴的 markdown 导入。配合独立文件，换机搬配置一步到位。

改动清单

host 半（lib/index.js）

  • Config 走 Schemastery：file / watch / maxHistory，非法配置在加载时报错而不是静默忽略
  • 修正 source 形态：改为官方 ContextFormed 里的 {kind:'plugin', plugin:name, form:'snapshot', sections:[…]}
  • 去重改为投影式：用 sessionProjections.register() 记录「本会话已注入过哪些块」，跨轮真去重
  • system 段去掉装饰线：text 就是原文，分隔交给框架的 "\n\n" join
  • watch 目录而非文件：避免编辑器「替换文件」后监听失效
  • 新增路由：GET /preview（真实装配）、POST /validate、GET /variables
  • save 做结构校验：块必须过一遍 schema 再落盘，坏数据不进文件

client 半（lib/client.js）

  • 三栏布局：块清单 / 编辑器 / 模型视角预览
  • 块拖动排序、悬停快捷启停、类型切换
  • order 轴可视化（叠官方段序列）
  • 报错上浮到界面（不再只写 console）
  • 历史 diff 视图 + 恢复预演
  • locale 词典补全新键（zh/en 必须齐全，否则 ctx.locale.register 抛错）
  • 保留：settings.section 注册范式、同源 fetch、无 CORS、不额外占端口

关键改动：注入消息的 source

官方 dsh-llm 的 MessageSourceMap 里并没有「随便一个 kind」这回事； kind:'plugin' 才需要 plugin 字段，而带语义的形态走 form。 官方 dsh-time-context 就是标准范例。 

// v1 —— lib/index.js（现状：游离 kind，语义不明）
injected.push({
  id: randomUUID(),
  role: "user",
  content: [{ type: "text", text: b.body }],
  source: { kind: b.kind },        // ← 'gw-project' 不在 MessageSourceMap 里
});

// v2 —— 对齐官方形态（dsh-time-context 同款）
createUserMessage({
  content: [{ type: "text", text: body }],
  source: {
    kind: "plugin",
    plugin: name,                       // '@gw/dsh-text-inject'
    form: "snapshot",
    sections: [{ name: `gw-text-inject:${b.name}`, text: body }],
  },
});

关键改动：系统段文本

// v1
text: `\n\n${"-".repeat(32)}\n${b.body}\n${"-".repeat(32)}`
//   ↑ 32 个短横线会原样进提示词，模型看到莫名其妙的分隔符

// v2 —— 原文即文本，框架自己会用 "\n\n" 把段拼起来
ctx.systemPrompt.section({ name: `gw-text-inject:${b.name}`, order, text: b.body });

验证方式（不猜，跑出来）

# 1. 装配结果离线看：dsh 会打印完整配置树，能看到你的 insert 行生效
dsh --profile web --dump-config

# 2. 装到独立 profile 里练，不污染日常 profile
dsh plugin --profile plugin-dev add ./dsh-text-inject
dsh --profile plugin-dev

# 3. 本地临时叠加层（name 必须绝对路径，相对路径会静默失败）
dsh web --patch ./scratch/cordis.yml

已实测的环境事实

  • web profile 的 cordis.patch.yml 里 gw-text-inject insert 行已存在，--dump-config 能打印出来（配置层没问题）
  • 同一份 patch 里 font / modlens 两行会报 patch: entry not found（本就 disabled，不影响启动）
  • 官方段 order 常量：harness:identity -1000 / deployment:persona 0 / PLAN_POLICY 500 / 工具段 1000–2900 / TOOLS_SDK 5000 / STRUCTURED_OUTPUT 9900
  • 段名重复在同层会直接抛错，所以 gw-text-inject:<名称> 这个命名前缀要保住
